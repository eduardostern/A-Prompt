    AI board (DeepSeek)

    In the terminal, TERM then ATDT DEEPSEEK calls a BBS whose sysop is DeepSeek V4.1 Flash: chat with it (or with the Bastard Operator From Hell, who may hang up on you), order a program that it writes in 8080 assembly and sends you by ZMODEM, or upload your own .ASM (F, then ZMODEM S) to have it fixed. It needs your own DeepSeek API key.

    No key yet.
    How do I get a key?
    1. Open platform.deepseek.com and sign up.
    2. Add a little credit on Top up. The API is pay as you go; with no balance, calls fail with "insufficient balance".
    3. Open API keys, choose Create new API key, name it "A-Prompt" and copy it (it starts with sk-; copy it now, you may not see it again).
    4. Paste it above and press Save.
    5. In the terminal: TERM, then ATDT DEEPSEEK.

    The key stays in this browser and goes only to api.deepseek.com; calls are billed to your DeepSeek account. Anyone using this browser profile can use it: press Forget, or delete the key on the API keys page, to revoke it.

    About

    CP/M 2.2 in your browser. And it dials out.

    • Dial real BBSes. Type TERM, then ATI for the phone book and ATDT 1 to call. Sound on: dial tone, beeps and the handshake screech.
    • Download files. Ctrl-] leaves TERM with the call up; then ZMODEM R or XMODEM.
    • Order a program from an AI. ATDT DEEPSEEK: DeepSeek V4.1 Flash writes 8080 code, the real ASM.COM assembles it, and it arrives by ZMODEM. Bring your own key (AI board panel).
    • Call the BOFH. B on the AI board. He may hang up on you.
    • Play. TETRIS, COLOR, or upload Zork and friends.

    A real CP/M 2.2 underneath: a complete Z80 CPU, BDOS with 8.3 files, FCBs, user areas and console, plus a browser-hosted CCP. The DRI binaries come from cpm.z80.de and are distributed under the CP/M license.

    Drive A: is a host folder by default. Export it as a .dsk image (or mount an existing one) to use raw-sector tools you upload, such as disk editors; none is bundled. Everything runs in memory; uploads are saved in this browser.

    Boards with a WebSocket gateway are called straight from your browser; for the rest this site's Worker relays the call, to a fixed list of boards only. ATM0 silences the modem.

    Source, issues and releases: github.com/eduardostern/A-Prompt

    AI provenance

    An effective Sino-American team. Built with OpenCode + DeepSeek V4.1 Flash for under $1 in model tokens ($0.92 for the build; other experiments excluded). Then Claude Code with Claude Opus 5.5 had to review it and fix what DeepSeek left behind: CP/M compatibility, the memory map, disk formats, SUBMIT, the clock and STAT. Final touches by Claude Fable 5.1, where the cheap tokens were not up to the task: BIOS DMA addressing, FCB extents (S2, F_OPEN) and ^S/^C on console output; the human's idea made TETRIS tune itself with CP/M 3's T_GET instead of a made-up timer port. Opus 5.5 later added the telnet modem, TERM, XMODEM, ZMODEM and the VT100 bell, and brought DeepSeek V4.1 Flash back as the AI board's sysop, one modem call away. No GPT or Grok. Both are transformers — the only other one here is in the power supply.

    A short field guide

    What is CP/M?

    CP/M — Control Program for Microcomputers — was the first widely standard operating system for microcomputers. It made software portable across dozens of incompatible 8080/Z80 machines.

    1974 → 1979

    Gary Kildall wrote CP/M at Digital Research. CP/M 1.4 arrived in 1976 and CP/M 2.2 — the version this emulator implements — in 1979. It became the default OS for business micros: Altair, Osborne, Kaypro, Xerox, North Star, Epson and many other 8080/Z80 machines.

    Why the Z80?

    CP/M was written for the Intel 8080. The Z80 is binary-compatible with the 8080, cheaper, and adds instructions and registers. Most CP/M software is plain 8080 code and runs happily on a Z80; the extra instructions only made some programs faster or more compact.

    The standardization trick

    CP/M split the machine into three layers: the BIOS (hardware-specific), the BDOS (files, console, disk directory) and the CCP (the A> prompt and commands). Programs call BDOS through CALL 5 and never touch the hardware directly. That is why one binary could run on machines with completely different floppy controllers.

    The shared conventions

    8.3 filenames, 128-byte records, FCBs, user areas, the transient program area (TPA), .COM executables and utilities like PIP, STAT, ED, ASM. These conventions were the “API” that made an ecosystem possible.

    What ran on it

    WordStar, dBASE II, SuperCalc, MultiPlan, Turbo Pascal, MBASIC, FORTRAN, COBOL, assemblers — and games: Sargon, Zork, Adventure, Nemesis. The 8-bit business machine era was largely a CP/M era.

    VisiCalc and SuperCalc

    VisiCalc (1979, Dan Bricklin and Bob Frankston) was the first spreadsheet and the “killer app” of personal computing. It did have CP/M ports, but they were niche: the HP 125 and Sony SMC-70 versions are the CP/M releases. The mass-market VisiCalc was for the Apple II, Atari, TRS-80 and IBM PC.

    The spreadsheet that actually shipped with CP/M business machines was SuperCalc (Sorcim, 1980; bundled with the Osborne 1). A-Prompt does not bundle either, but the Software card links to the SuperCalc archives; install the zip, run INSTALL, choose ANSI Standard, save, then run SC.

    This machine

    64 KB RAM, Z80, TPA 0100h–FBFFh, drives A:–D:, CP/M 2.2 BDOS and CCP, FCBs, 8.3 files, ADM-3A/VT52/ANSI terminal profiles and mountable .dsk images.
